## 二、怎么用

### 方式 1：WebUI（推荐）

| 入口 | 双击 | 地址 | 作用 |
|---|---|---|---|
| 主界面 | `启动WebUI.bat` | http://127.0.0.1:9874 | 总入口，点里面的「推理」会拉起推理页 |
| 推理页 | `启动推理页.bat` | http://127.0.0.1:9872 | **TTS 就在这里做**（可直接开，不必先开主界面） |

两个都启动后，在推理页填：

| 项 | 值 |
|---|---|
| 参考音频 | `output\denoise_opt\` 里任意一段，例如 `vocals.wav_0000040640_0000210560.wav` |
| **参考音频的语种** | **日文** ⚠️ 见坑 1 |
| **参考音频的文本** | **该段音频的日文原文**（不是音素串！）⚠️ 见坑 2 |
| 需要合成的语种 | 日文（中文文本选中文） |
| GPT 模型列表 | `makoto-e15.ckpt` |
| SoVITS 模型列表 | `makoto_e8_s200.pth` |

上面那段参考音频对应的原文（可直接复制）：

```
おはよう春ちゃん。ごめんごめん春。入学式遅れるよ。
```

也可以从 `output\asr_opt\denoise_opt.list` 该行第 4 列取，`logs\makoto\2-name2text.txt` 第 4 列同样是原文。

**⚠️ 最容易踩的三个坑**

1. **「参考音频的语种」必须选「日文」。** 它默认是「中文」，填日文内容却按中文处理
   （日志会打印 `当前使用g2pw进行拼音推理`），音素全废，模型只吐十几个 token 就停，
   **输出只有 0.7 秒**。我已把推理页两个语种下拉框的默认值改成「日文」。

2. **参考文本填日文原文，不要填音素串。**
   README_MAKOTO 让你从 `2-name2text.txt` 第 2 列取音素串，**那是错的**。
   框架推理时会把 `prompt_text` 再过一遍 pyopenjtalk：音素串会被当成罗马字重新解析，
   53 个 token 膨胀成 **178 个乱码音素**（`o [ h e ] cl ch i e ] i w a ...`），
   模型把这些乱码念出来，**凭空多出约 10 秒音频**。
   填日文原文则得到 58 个音素，和训练格式的 53 个几乎一致。

   实测（参考音频同上）：

   | 参考文本 | 目标文本 | 输出 |
   |---|---|---|
   | 音素串 | 「あ」（1 音节） | **10.74s** ❌ 与目标无关 |
   | 音素串 | 短句（17 音节） | 10.18s ❌ 与目标无关 |
   | **日文原文** | 「あ」（1 音节） | **0.98s** ✅ |
   | **日文原文** | 短句（17 音节） | **3.10s** ✅ |

   判据很直白：填音素串时，目标只写一个字也照样生成 10 秒——那 10 秒不是你要的文本。

3. **`say.py` 的目标语种**：中文文本要加 `--lang zh`，否则日语 G2P 读不出汉字，输出只有零点几秒。

**采样参数**：滑块默认就是 `top_k=15 / top_p=1 / 温度=1`（README 验证过的组合），不用动。
若改成 `top_k=20 / top_p=0.6 / 温度=0.6`，会**模型不吐 EOS**——生成 60 秒，其中只有约 5 秒有人声。
遇到“音频很长但大部分没声音”，把这三个值调回 15 / 1 / 1 再生成。

**故障速查**

| 症状 | 原因 | 解决 |
|---|---|---|
| 输出只有约 0.7 秒 | 参考语种选成「中文」，日文被拼音引擎处理 | 参考语种改「日文」 |
| 输出比预期长很多（约 10 秒起），且与文本长度无关 | 参考文本填了音素串 | 改填日文原文 |
| 输出很长但大多静音 | `top_k/top_p/温度` 设成 20/0.6/0.6 | 改回 15/1/1 |
| 中文文本输出只有零点几秒 | 目标语种没选「中文」 | 语种改「中文」 |
| 输出很短但设置都对 | 目标文本本身就很短 | 正常现象，写长一点 |

> ⚠️ **必须让 localhost 绕过系统代理**。本机装了代理（`127.0.0.1:7897`），如果不绕过，
> Gradio 启动时自检 localhost 会失败并直接退出（报 `When localhost is not accessible...`）。
> 两个 `.bat` 里都已经加了 `set NO_PROXY=localhost,127.0.0.1,::1`；
> 如果你手动敲 `runtime\python.exe webui.py`，要自己在 PowerShell 里先 `$env:NO_PROXY='localhost,127.0.0.1,::1'`。

### 方式 2：命令行合成

```bat
合成语音.bat "おはよう、春ちゃん。今日もいい天気だね。"
合成语音.bat "僕は橘真琴。" my.wav
```

或直接调用脚本（参数更全）：

```bat
GPT-SoVITS\runtime\python.exe -X utf8 say.py "文本" -o out.wav
```

| 参数 | 默认值 | 说明 |
|---|---|---|
| `-o` | `makoto_output.wav` | 输出路径 |
| `-r` | `output\denoise_opt\vocals.wav_0000040640_0000210560.wav` | 参考音频 |
| `--gpt` | `GPT_weights_v2\makoto-e15.ckpt` | GPT 权重 |
| `--sovits` | `SoVITS_weights_v2\makoto_e8_s200.pth` | SoVITS 权重 |
| `--device` | `cuda` | `cuda` / `cpu` |
| `--top-k` | 15 | 越小越稳定，越大越多样 |
| `--temperature` | 1.0 | 越高越多变 |
| `--speed` | 1.0 | 语速 |
| `--lang` | `ja` | 目标文本语种；**中文文本必须用 `--lang zh`** |
| `--seed` | 42 | 随机种子，固定则结果可复现 |

## 六、注意事项

1. **LoRA 权重不能用 `torch.load()` 直接读**。它使用自定义 `b'03'` 文件头，必须用
   `process_ckpt.load_sovits_new()` 加载（该函数会把 `03` 换成 `PK`）。直接 `torch.load()`
   会报 `UnpicklingError`，这是框架设计行为，不是文件损坏。

2. **`runtime\Lib\site-packages\users.pth` 里是绝对路径**。框架从 D: 盘复制过来时，
   该文件已改写为 `C:\Users\1\Desktop\makoto\GPT-SoVITS`。如果你以后移动这个文件夹，
   需要同步改这个文件里的 6 行路径（对应 README Q9）。原件备份在同目录 `users.pth.bak_D`。

3. **`say.py` / `.bat` 必须用框架自带的 runtime 解释器**（`GPT-SoVITS\runtime\python.exe`），
   不要用系统 Python，依赖环境不通用。

4. **本机 PATH 有问题**：环境变量里 `%SystemRoot%` 被写成了 `%Sys;emRoot%`，导致
   `cmd`、`robocopy` 等 System32 下的命令不在 PATH 上。`启动WebUI.bat` 和
   `合成语音.bat` 内部都用绝对路径调用，不受影响；但你在别的终端里敲 `cmd` 可能会找不到。

5. 首次合成较慢（显卡预热 + 模型加载），之后同一进程内会快很多。

6. **日文参数乱码时**：`.bat` 通过命令行传参，若你的 cmd 代码页不对，日文可能变问号。
   改用 PowerShell（下面这条已实测通过），或把文本写进 `say.py`：

   ```powershell
   & 'C:\Users\1\Desktop\makoto\GPT-SoVITS\runtime\python.exe' -X utf8 `
     'C:\Users\1\Desktop\makoto\say.py' "おはよう、春ちゃん。今日もいい天気だね。"
   ```

7. 模型仅供学习研究使用，生成音频请标明 AI 生成来源。
